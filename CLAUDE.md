# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Omarchy Sleepwalker: an Omarchy plugin (`io.github.tymurbogach.sleepwalker`) that adds a "Laptop"
indicator to Omarchy's bar. Toggling it holds a `systemd-inhibit --what=handle-lid-switch`, so closing
the laptop lid only powers off the panel instead of suspending. It ships as a clone of Omarchy's stock
indicator strip plus one new indicator — not a separate bar widget.

## Commands

There is no build step, package manager, or test suite — this is a QML plugin plus bash scripts. Mandatory
verification workflow after any substantive change (see `omarchy.md` for full detail):

```bash
omarchy plugin validate .
qmllint -I "$OMARCHY_PATH/shell" <changed .qml files>

# from-zero reinstall cycle
omarchy plugin disable io.github.tymurbogach.sleepwalker --yes
omarchy plugin remove  io.github.tymurbogach.sleepwalker --yes
ls ~/.config/omarchy/plugins/io.github.tymurbogach.sleepwalker/   # MUST NOT exist
omarchy plugin add . --enable --yes
omarchy-restart-shell                  # only reliable QML reload
```

Then verify cold-start by hand: bar renders, click toggles the indicator, lid close behaves,
`omarchy plugin list --json` shows it, disable/enable/restart/remove all work cleanly.

Fast local iteration without a full reinstall: copy the repo into
`~/.config/omarchy/plugins/io.github.tymurbogach.sleepwalker/`, then trigger `rescanPlugins` +
`omarchy-restart-shell`.

Refresh the stock indicator clone after an Omarchy update:

```sh
./install.sh --sync-stock
```

## Architecture

Three moving parts, one shared state directory, no polling:

- **`Service.qml`** (entry point `service`, `IpcHandler` target `sleepwalker`) — owns the lid-inhibit
  child process and the toggle state. Holds `systemd-inhibit … sleep infinity` as a child `Process`
  exactly while the toggle is on (no systemd unit — `omarchy plugin add` alone is a working install).
  Writes are serialized through `runWrite`/`writerBusy` so a rapid second toggle queues instead of racing
  a second bash invocation over the same state files.
- **`Indicators.qml`** (entry point `barWidget`) — a clone of Omarchy's stock indicator strip
  (`$OMARCHY_PATH/shell/plugins/bar/widgets/Indicators.qml`), regenerated by `install.sh --sync-stock`
  with three documented patches (see the file's own header comment): relative import path fix, `Laptop`
  added to `defaultIndicatorEntries`, and the stock `IpcHandler` removed to avoid a handler-collision
  warning against the disabled built-in. **Never hand-edit this file** — always regenerate it.
- **`indicators/Laptop.qml`** — the new indicator. Binds reactively to `Service.qml` via
  `bar.shell.serviceFor("io.github.tymurbogach.sleepwalker")` when available; falls back to shelling out
  to the bundled CLI (`bin/omarchy-sleepwalker`, resolved relative to the plugin, never via `PATH`) plus a
  30s poll when the service is unreachable. `indicators/{Dictation,Dnd,NightLight,Reminder,
  ScreenRecording,StayAwake}.qml` are verbatim copies of Omarchy's stock indicators, also refreshed by
  `--sync-stock` — don't edit those by hand either.
- **`bin/omarchy-sleepwalker`** — user-facing CLI (`status`, `lid on|off|toggle`, `lock on|off|toggle`,
  `doctor`). Reads/writes the same state files as `Service.qml` and `Laptop.qml`, so all three views of
  the toggle always agree.
- **`bin/omarchy-system-lid-close`** — shim installed to `~/.local/bin` (sorts ahead of
  `/usr/share/omarchy/bin` on `PATH`) so a lid-close event skips the stock lock when the toggle is on and
  lock-on-lid is off, while still reconciling displays via the stock clamshell script. Delegates 1:1 to
  the real script otherwise.

State lives entirely under `~/.local/state/omarchy/toggles/`: presence of `sleepwalker` (preferred) or
`lid-ignore` (legacy, read-only) means the toggle is on; presence of `lid-lock` means lock-on-lid is
opt-in-enabled. No file content is read, only existence — `touch`/`rm -f`.

`install.sh` and `uninstall.sh` also carry substantial legacy-migration logic (old plugin id
`io.github.tymurbogach.lid`, pre-0.2.0 systemd inhibit units, pre-0.2.0 derived-clone plugin dirs,
pre-0.2.0 separate bar-widget layout entries). When touching install/uninstall, preserve this migration
path — real installs still hit it — rather than assuming a clean slate.

## Conventions specific to this repo

- Everything (code, docs, commits) is English.
- No symlinks anywhere in the repo (`omarchy plugin validate` rejects them).
- Zero-residue on remove: `uninstall.sh` must leave no files, caches, or stray `shell.json` entries
  behind, and only removes files it can verify are its own (see the `ours()` check in `uninstall.sh`).
- Commits: English, imperative, one concern per commit, no AI attribution.
